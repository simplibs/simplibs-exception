# 📦 `assert_exception_class` — Komplexní audit třídy výjimky

`assert_exception_class` je hlavní orchestrátor (vzorec **Facade**) testovací infrastruktury pro výjimky v knihovně `SimpleException`. Sjednocuje čtyři dílčí kontroly do jedné sekvenční pipeline.

> 💡 **Hledáte podrobný návod a ukázky?** Přejděte na [Uživatelský průvodce s příklady](USER_GUIDE.md).

---

## ⚙️ Architektonické principy
- **Facade Pattern** ➔ Jeden vstupní bod pro kompletní audit struktury výjimky.
- **Fail‑Fast brána** ➔ Pokud selže kontrola dědičnosti, pipeline se okamžitě zastaví.
- **Fluid API** ➔ Funkce vrací zachycenou instanci výjimky z testu výchozích hodnot.
- **Hierarchie upovídanosti** ➔ Globální `verbose` řídí subtesty, `verbose_constructor` je jemné ladění.

---

## 🎛️ Parametry funkce

### Ukázka hlavičky
```python
def assert_exception_class(
    subtests: Any,
    exc_class: type[Any],
    *,
    expected_parents: type[Any] | tuple[type[Any], ...] | UnsetType = UNSET,
    exact_match: bool = False,
    startswith: bool = False,
    verbose: bool = True,
    verbose_constructor: bool = False,
    intro: str = "",
    deep_check: bool = True,
) -> Any:
```
### Popis parametrů
#### Povinné parametry:
- `subtests` ➔ The native pytest subtests fixture manager instance.
- `exc_class` ➔ Exception class to validate.

#### Doplňující parametr:
- `expected_parents` ➔ Volitelný parametr pro kontrolu předků, z kteréch třída dědí
  - Tento parametr se hodí pro testování zda i další předci třídy jsou v její MRO

#### Parametry pro specifikaci porovnání:
NOTE: Standardní porovnávání seprovádí přes in, a je tak univerzální v ohledu že můžete zadávat jakýkolv text který se musí objevit ve výpisu.
Ale jeho nevýhodou je že nedosahuje úplné přesnosti a pro ni zde slouží tyto další dva parametry.
- `exact_match` ➔ Bool parametr umožňují porovnání na přesnou shodu (default=False).
  - Tento parametr se hodí pokud chcete otestovat přeshnou shodu zadávaných dat s výstupem
- `startswith` ➔ Bool parametr pro nastavení hluboké kontroli (default=False).
  - Tento parametr se hodí pokud chcete zajisti kontrolu že výstup začíná předaným textem

#### Parametry pro nastavení výpisu:
- `verbose` ➔ Bool parametr pro nastavení upovídanosti výisu testů (default=True).
  - Tento parametr rozhoduje o tom, zda výpis testů byude podrboný a nebo stručný
  - `True`aktivuje subtesty pro celou pipeline
  - `False` je pro čistý kompaktní výstup
- `verbose_constructor` ➔ Bool parametr pro nastavení upovídanosti testů konstruktru (default=False)
  - Umožňuje v případě chyby konstruktoru vypsat si podrobný výpis kroků
  - `True` ativuje subtesty i pro konstruktor
  - `False` vypne subtesty pro konstruktor.
- `intro` ➔ Textový parametr pro úvodní test testů (default="").
  - Tento parametr umožňuje nastavit s jakým testem se budou testy vypisovat

### Parametr pro nastavení stylu testování:
- `deep_check` ➔ Bool parametr pro nastavení hluboké kontroli (default=True).
  - Tímto parametrem rozhodujete o hloubce rozsahu kontroli
  - `True` aktivuje kompletní audit - všechny 4 kroky
  - `False` pro kontrolu dědičnost a výchozích hodnot

## 🧭 Pipeline kroků

Orchestrátor provádí kroky v tomto přesném pořadí:

1) **Inheritance Contract** (`assert_class_inheritance`)  
   Ověří:
   - že výjimka dědí `BaseException` a `SimpleExceptionData`. 
   - případné další předky jsou li zadané přes parametr `expected_parents`

```python
    # Ukázka interního předávání parametrů
    assert_class_inheritance(
        subtests,
        exc_class,
        expected_parents=expected_parents,
        verbose=verbose,
        intro=intro
    )
```

3) **Class Defaults Reflection** (`assert_class_defaults`)  
   - Ověří výchozí hodnoty instance bez argumentů.
   - Vrací instanci výjimky pro případné dalščí použití

```python
    # Ukázka interního předávání parametrů
    exc = assert_class_defaults(
        subtests,
        exc_class,
        exact_match=exact_match,
        startswith=startswith,
        verbose=verbose,
        intro=intro
    )
```

3) **Constructor Propagation** (`assert_class_constructor`)  
   - Ověří správné uložení argumentů konstruktoru.  
   - Spouští se jen při `deep_check=True`.
   - Verbose je průnikem verbose a verbose_constructor

```python
    # Ukázka interního předávání parametrů
    if deep_check:
        assert_class_constructor(
            subtests,
            exc_class,
            verbose=verbose and verbose_constructor,
            intro=intro
        )
```

4) **Public API Contract** (`assert_class_interface`)  
   - Ověří přítomnost dunder metod a serializátorů.  
   - Spouští se jen při `deep_check=True`.
```python
    # Ukázka interního předávání parametrů
    if deep_check:
        assert_class_interface(
            subtests,
            exc_class,
            verbose=verbose,
            intro=intro
        )
```

## 🔍 Rychlé příklady použití

```python
# 1. Standardní kompletní audit
assert_exception_class(subtests, MyError)

# 2. Přísná shoda textových defaultů (Exact match)
assert_exception_class(subtests, MyError, exact_match=True)

# 3. Kontrola pouze začátku textu (Prefix match)
assert_exception_class(subtests, MyError, startswith=True)

# 4. Tichý režim bez pytest subtestů
assert_exception_class(subtests, MyError, verbose=False)

# 5. Upovídaný režim pro zjištění chyby v konstruktoru
assert_exception_class(subtests, MyError, verbose_constructor=True)

# 6. Rychlý základní test (bez kontroly konstruktoru a API)
assert_exception_class(subtests, MyError, deep_check=False)
```
